# Changelog

## 1.3.1

Accuracy fixes. No request changes; `track_payment` responses gain fields and its note is corrected.

- **`track_payment` no longer reports a no-nexus $0 as "No sales tax owed".** It read a top-level `nexus_warning` the API never returns, so a seller with no nexus answer for the buyer's state (every keyless call outside the shared demo nexus profile) got "No sales tax owed in FL for this transaction type." The note now says the $0 is a default, not a determination, and gives the amount owed once nexus is set (e.g. "If you have nexus in WA, this payment owes $6.50 (6.5%)"). New response fields: `tax_if_nexus`, `nexus_status` (from `resolution.nexus`), `exemption`, `resolution`, `mode`, and `demo_note` on keyless calls. `nexus_warning` now carries the API's `NEXUS_NOT_CONFIGURED` advisory (keyed) or `nexus_note` (keyless). A $0 resting on your own `hasNexus: false` says so; a genuinely exempt sale still says "No sales tax owed". An unresolved `resolution.taxability` is appended to the note.
- `track_payment` `tax_rate` is the rate that produced `tax_owed` (`applied_rate`). Keyless calls used to show the location rate next to a $0.
- **`calculate_tax` description is accurate for keyless calls.** It promised jurisdiction, audit trail and advisories; a keyless call returns an estimate (`total_tax`, `combined_rate`, `applied_rate`, `confidence`, `resolution`, plus `tax_if_nexus` / `exemption` when a $0 is a default). A free API key adds the jurisdiction breakdown, audit trail, advisories with citations, history and your own nexus. README and ClawHub skill updated to match.
- `track_payment`'s `work_type` description lists all eleven work types (it named only the first six; the enum already accepted all eleven). Tests now pin the `work_type` descriptions and the `transaction_type` enums on `calculate_tax` and `ingest_transactions` (including `payment_processing_fee`, `web_hosting`, `software_maintenance`, `it_support`) to the API's list.

## 1.3.0

Adds `intent` and documents `resolution` on `calculate_tax`. No result changes when you omit `intent`.

Needs the AgentTax API release that accepts `intent` and returns `resolution` (live on agenttax.io since 2026-10-21). If you point `AGENTTAX_BASE_URL` at an older API, omit `intent`.

- **New optional `intent` argument on `calculate_tax`** (`estimate` | `record`). `estimate` quotes a price before a wallet signs: it is computed and counts toward your monthly quota, but nothing is saved to transaction history, it never counts toward nexus revenue, and it ignores the Idempotency-Key. `record` (the default for keyed calls) logs the calculation as before. Keyless demo calls are always estimates. The server sends `intent` only when you pass it, so existing calls are byte-for-byte unchanged.
- **`resolution` in the `calculate_tax` response** (from the same API deploy). `resolution.location`, `resolution.nexus` and `resolution.taxability` each report `status` (`resolved` | `partial` | `unknown`), `basis` and `detail`. `total_tax` is never withheld; to treat "unknown" as "do not charge", branch on `resolution.*.status`. The README has an example.
- `calculate_tax` keeps its writing annotation (`readOnlyHint: false`): annotations are static and a keyed call without `intent: "estimate"` still writes to history.
- **`work_type` accepts the five classification work types** on `calculate_tax` and `track_payment`: `payment_processing`, `web_hosting`, `software_maintenance`, `it_support`, `custom_software` (the API has accepted them since 2026-10-16; the 1.2.0 enum rejected them). `track_payment` maps each to its own `transaction_type` (`payment_processing_fee`, `web_hosting`, `software_maintenance`, `it_support`; `custom_software` is answered as a SaaS sale, since `track_payment` has no attestation). The Stripe webhook's `metadata.work_type` still accepts its five original values. Description guessing is unchanged and never produces these types.
- **`calculate_tax` carries the classification facts** and passes them through to the API unchanged, all optional: `payment_provider_type` (with `transaction_type: "payment_processing_fee"`), `it_support_scope` (`it_support`), `includes_prewritten_software_access` (`web_hosting`), `custom_software_attestation` (required with `work_type: "custom_software"` for the custom-software answer) and `maintenance_contract` (`software_maintenance`, including `itemized_amounts`). Names, nesting, enum values and strictness match the API: an unknown key inside `custom_software_attestation`, `maintenance_contract` or `itemized_amounts` is refused before the call is sent. Without them the API gives its conservative default, as before.
- **`transaction_type` accepts the four classification transaction types** on `calculate_tax` and `ingest_transactions`: `payment_processing_fee`, `web_hosting`, `software_maintenance`, `it_support` (the API has accepted them since 2026-10-16).
- `payment_provider_type`, `it_support_scope`, `use_context` and `digital_content_type` on `calculate_tax` are trimmed and lowercased before the enum check, as the API does, so `"Bank "` is accepted and sent as `"bank"`. `ingest_transactions` records already pass the same facts through to the API.
- The enums now live in `classify.js` and a test pins them to a copy of the API's values (`test/fixtures/api-calculate-enums.json`).
- No other tool changed.

## 1.2.0

Tax-safety release for `track_payment`. Some results change; read before upgrading.

- **Guessed consulting and trading are no longer exempt.** 1.1.1 guessed a work type from `description` and sent it as if you had declared it. A description that looked like consulting ("SOC 2 audit platform subscription", "tax advice") sold to an Arizona buyer came back $0 under the AZ professional-services exemption, and one that looked like trading ("game asset pack", "token swap fee") came back $0 in every state as a financial service. Both guesses are now taxed as SaaS. If the sale really is consulting or trading, pass `work_type` and the exemption applies as before.
- **New optional `work_type` argument on `track_payment`** (`compute` | `research` | `information_service` | `content` | `consulting` | `trading`). It overrides the description and is treated as a declaration. Pass it for an exact answer.
- **Guessed compute and research are unchanged** from 1.1.1. They are not exemptions, but those categories can tax less than SaaS in some states (e.g. CT, MD, SC, TN, WV). Pass `work_type` for an exact answer.
- **`is_b2b` is sent only when you pass it.** 1.1.1 always sent `is_b2b: false`, which silently declared every buyer a consumer. Ohio sellers to consumers: pass `is_b2b: false`, or the sale is now taxed (Ohio exempts SaaS and data processing only for a declared consumer; an unknown buyer is taxed). With `is_b2b` omitted, AgentTax may also auto-detect a business buyer when the counterparty has a KYA principal record marked as a business, and apply B2B rules (e.g. Maryland 3%, Iowa B2B exemption); 1.1.1's explicit `false` blocked that. Pass `is_b2b` yourself if you know the buyer.
- The `track_payment` response has a new `classification` field saying where the work type came from (`explicit`, `inferred_from_description` or `default`) and, when a consulting or trading guess was not used, a note telling you to resend with `work_type`.
- No other tool changed. `calculate_tax` and `ingest_transactions` already sent only what you gave them.
